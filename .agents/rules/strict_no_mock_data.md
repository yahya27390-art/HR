# Strict Rule: No Dummy, Mock, or Fabricated People/Names (منع تام للأسماء والأشخاص الوهميين)

## Rule Description
**يُمنع منعاً باتاً ومطلقاً اختراع أو توليد أو إدراج أي أسماء أشخاص وهميين أو عملاء تجريبيين أو محادثات مفبركة في أي برنامج أو منصة أو قاعدة بيانات يتم تنفيذها مع المستخدم.**

## Binding Guidelines:
1. **البيانات الحقيقية فقط (Real Authenticated Data Only)**:
   - يجب أن تعتمد المنصات والبرامج بنسبة 100% على البيانات والمحادثات والرسائل الفعلية المستلمة من الـ APIs الرسمية، قواعد البيانات الحقيقية، أو الويب هوك اللحظي.
2. **التعامل مع القنوات الجديدة أو الفارغة (Zero-Data / Empty States)**:
   - في حال كانت القناة (مثل تيك توك، أو ماسنجر، أو واتساب) جديدة أو لا تحتوي على رسائل واردة فعلية حتى الآن، يتم عرض شاشة حالة فارغة واضحة ومهنية، مثل:
     - *"لا توجد رسائل واردة حالياً (القناة متصلة حياً وبانتظار رسائل العملاء الفعلية عبر الويب هوك)"*.
   - **لا يجوز أبداً** ملء القوائم بأسماء وهمية أو أشخاص تجريبيين لمحاكاة الواجهة.
3. **الاختبارات التقنية (Technical System Testing)**:
   - إذا تطلب الأمر إجراء فحص اتصال تقني (Health Check / Ping)، يجب استخدام مسميات تقنية بحتة (مثل `System-Ping` أو `Webhook-Test-Event`) مع تصنيفها كاختبار تقني، دون انتحال هوية عملاء حقيقيين أو كتابة أسماء عربية مفبركة.
